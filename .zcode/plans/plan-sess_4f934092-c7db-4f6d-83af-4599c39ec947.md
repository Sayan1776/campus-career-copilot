# Make Campus Career Copilot serve ALL engineering departments

## Root cause

The `users` table already stores `department`, and most UI components render skill strings generically. The CS-only behavior comes from three layers:

1. **Department never reaches the AI.** `analyzeResume(text, targetRole)` and `generateSkillJourney(skill, targetRole)` only receive a role. A Mechanical student gets evaluated against CS expectations because prompts have CS few-shot examples ("System Design", "SQL optimization", MDN/python docs).
2. **The only role picker is CS-only.** `app/(dashboard)/student/upload/page.tsx` offers 6 CS roles; `'Software Engineer'` is the fallback default in 4 places that feed AI prompts.
3. **Seed data, DB default, and marketing copy are 100% CS.** `app/api/seed/route.ts` seeds only CS skills/gaps/roles/companies; migration `0004` defaults `department` to `'Computer Science'`; the landing page shows DSA/SYSTEM radar axes and "Software Engineer 2026".

## Changes

### 1. New shared config — `lib/departments.ts` (new file)
Single source of truth, replacing the 3 inconsistent department lists:
- `DEPARTMENTS`: all major branches — Computer Science, Information Technology, Electronics & Comm, Electrical, Mechanical, Civil, Chemical, Data Science & AI, Production/Industrial, Biotech, "Other".
- `ROLES_BY_DEPARTMENT`: curated 6–8 realistic target roles per department (e.g. Mechanical → Design Engineer, Manufacturing Engineer, Thermal/CFD Engineer, CAD/CAM Engineer, Quality Engineer, Automotive Engineer, PSU Engineer via GATE; Civil → Site Engineer, Structural Engineer, Construction Manager, Geotechnical Engineer...; ECE → VLSI Design Engineer, Embedded Systems Engineer, Telecom Engineer...; etc.).
- `CROSS_DISCIPLINARY_ROLES`: roles any branch can target (Product Manager, Data Analyst, Consultant, Business Analyst...).
- Helper `getRolesForDepartment(dept)` returning department roles + cross-disciplinary roles.

### 2. Thread department into the AI layer — `lib/ai/client.ts`
- `analyzeResume(resumeText, targetRole, department)` and `generateSkillJourney(skill, targetRole, department)`: add department to both prompts, instructing the model to benchmark against what employers hiring for that role expect from graduates of that branch (e.g. CAD/FEA gaps for a Mechanical student, not "System Design").
- Neutralize CS few-shot examples: resume prompt's "System Design / SQL optimization" example → domain-neutral wording; journey prompt keeps the YouTube-search-URL rule but drops python/MDN specifics for "official documentation for the relevant domain".
- Remove the `'Software Engineer'` default parameter on `generateSkillJourney`.
- `generateResumeLatex` is already domain-neutral — untouched.

### 3. API routes
- `app/api/resume/analyze/route.ts`: fetch `department, target_role` from `users` **before** analysis; resolve targetRole as: form value → saved `target_role` → first suggested role for the student's department. Pass department to `analyzeResume`. Notification text uses the resolved role.
- `app/api/student/journeys/route.ts`: select `department` alongside `target_role`; pass both to `generateSkillJourney`; drop the `'Software Engineer'` fallback (use saved target or department default).
- `app/api/auth/set-role/route.ts`: accept optional `department` in the body; include it in the Supabase upsert when the invite code resolves to `student`.
- `app/api/seed/route.ts`: full multi-department demo cohort — 18 students spread across ~6 branches, each with per-department skill pools (e.g. AutoCAD/SolidWorks/MATLAB/FEA for Mechanical; STAAD Pro/AutoCAD/Primavera for Civil; VLSI/Verilog/PCB design for ECE), per-department gap distributions, matching target roles, and mixed company drives (L&T, Tata Steel, Siemens, Bosch, Reliance alongside Microsoft/Google/TCS).

### 4. Student-facing UX
- `app/(public)/signup/page.tsx`: add a department `<Select>` (populated from `lib/departments.ts`); sent with the set-role call and stored for student accounts.
- `app/(dashboard)/student/upload/page.tsx`: load the student's profile via existing `/api/profile`; render department-filtered roles + cross-disciplinary roles + a **"Custom role…"** free-text option (so literally any job is selectable); default to the student's saved `target_role` or first role for their department.
- `app/(dashboard)/settings/page.tsx`: replace the local DEPARTMENTS list with the shared config (adds Chemical etc.); target-role free-text input gets a `<datalist>` of the student's department's suggested roles.
- `components/ResumeBuilder.tsx`: default target role empty-with-placeholder instead of `'Software Engineer'`; generic placeholders (degree, skills, "tools used" label).

### 5. Neutralize CS display fallbacks & marketing
Replace `|| 'Software Engineer'` / `|| 'Computer Science'` display fallbacks with neutral text ("—" / "Not set") in:
- `app/(dashboard)/student/dashboard/page.tsx`
- `app/(dashboard)/campus/peers/page.tsx`, `PeerProgressClient.tsx` (+ generic search placeholder), `[peerId]/page.tsx`
- `app/(dashboard)/recruiter/candidates/page.tsx`
- `app/(dashboard)/tpo/dashboard/page.tsx`
- `app/(dashboard)/recruiter/post-jd/page.tsx` (generic skill-chip placeholder)
- `components/landing/InstrumentPanel.tsx`: radar axes DSA/SYSTEM → neutral labels (CORE SKILLS / DOMAIN / TOOLS / PROJECTS / COMM); "Software Engineer 2026" card → mixed-department examples; queue rows include MECH/CIVIL/EEE.

### 6. DB migration — `supabase/migrations/0005_drop_department_default.sql` (new file)
`ALTER TABLE users ALTER COLUMN department DROP DEFAULT;` so new users are no longer silently defaulted to Computer Science (existing rows left as-is; users can update via Settings).

## What stays unchanged
Matching logic (recruiter JD ↔ candidate skills overlap) already compares free-text skills, so it works for any branch once resumes are analyzed in-domain. Journey components, radar chart, competency list, TPO analytics aggregation, Firebase/push, and auth flow are all data-driven and need no structural change.
