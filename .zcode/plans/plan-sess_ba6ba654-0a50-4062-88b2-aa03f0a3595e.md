## Plan: Speed up page compilation & navigation

### 1. Enable Turbopack for development (`package.json`)
Change the dev script from `next dev` to `next dev --turbopack`. Turbopack is the Rust-based successor to Webpack and provides dramatically faster HMR and page compilation in Next.js 14.2+.

### 2. Move `NotificationListener` out of the root layout (`app/layout.tsx` → `app/(dashboard)/layout.tsx`)
Firebase Messaging is only needed for authenticated users. Move `<NotificationListener />` from the root layout into the dashboard layout so that public pages (login, signup, about, landing) don't load the Firebase Messaging SDK.

### 3. Extract `signOut` into a server action (new file `app/actions.ts`, update `components/Sidebar.tsx`)
Replace the direct `firebase/auth` import in the Sidebar with a lightweight server action that calls `signOut` server-side. This removes Firebase Auth from the dashboard client bundle entirely (it's only needed on login/signup pages).

### 4. Add build optimizations to `next.config.js`
```js
const nextConfig = {
  reactStrictMode: true,
  experimental: {
    optimizePackageImports: ['lucide-react', 'recharts', 'framer-motion'],
  },
  serverComponentsExternalPackages: ['firebase-admin', 'pdf-parse'],
};
```
- `optimizePackageImports` improves tree-shaking for large libraries
- `serverComponentsExternalPackages` ensures server-only packages are never accidentally bundled client-side

### 5. Optionally: Lazy-load `MotionConfig` providers
If framer-motion is still a concern after the above changes, we can split the `Providers` component to only include `MotionConfig` inside the dashboard route group (where it's actually used), keeping public pages free of framer-motion overhead.

### Expected outcome
- Turbopack alone typically gives **2-5x faster** HMR/compilation in dev
- Moving Firebase Messaging out of the root layout removes ~200KB+ from public pages
- Server action for signOut removes Firebase Auth (~300KB+) from the dashboard shared bundle
- `optimizePackageImports` reduces duplicate module entries in compiled chunks
